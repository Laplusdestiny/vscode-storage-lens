# VS Code Storage Lens 設計書

日付: 2026-11-16
状態: 承認済み(2026-11-16)。5.2〜5.5 のうち「作り手の判断」とした5点は agent-council での議論待ち(実装では `src/core/policy.ts` に集約して後から変えやすくする)

## 1. 目的と背景

ディスクが埋まってきたため、VS Code が使ううちに溜め込むファイルを減らしたい。
そのために、VS Code 自体の中から「どこに・どれだけ」溜まっているかを一目で見えるようにし、
消してよいものはその場で消せるようにする拡張機能を作る。

使っていない拡張機能も削除対象にしたいが、「使っていない」の自動判定はしない。
容量の大きいものが上に来る並びと「無効化済み」の印で、ユーザーの目に付くようにし、
最終的な判断はユーザーが行う。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- 今開いている環境(ローカルなら手元 PC、リモート接続中なら接続先サーバー)について、次をサイドバーに一覧表示する。
  - キャッシュフォルダのパスと容量
  - 拡張機能フォルダのパスと容量(拡張ごと)
  - その他、使ううちに膨らむ削除可能なフォルダのパスと容量
- 削除可能なものを選んで削除できる。
- 拡張機能をアンインストールし、ウィンドウをリロードできる。
- VS Code 起動中に消せないものは、フォルダをエクスプローラーで開けるようにする。

### 非ゴール
- ローカルとリモートを同時に表示すること。リモート接続中は接続先だけを対象にする(手元 PC のキャッシュは、ローカルでウィンドウを開いたときに見る)。
- 拡張機能フォルダを直接削除すること(容量の集計のみ。削除はアンインストール経由)。
- 「使っていない拡張機能」の自動判定(使用記録・最終使用日の推定など)。
- 動作の重さ(起動時間・CPU)の分析。目的はディスク容量。
- 定期実行・自動削除。

### アンチゴール(これをやったら失敗)
- `User/settings.json`、キーボードショートカット、スニペットなど、ユーザー設定を消してしまう。
- 今使っているリモートサーバー本体や、今開いているワークスペースの状態を消して、VS Code を壊す。
- 確認なしに削除する。

## 3. 制約

- 拡張機能は「今のワークスペースが動いている側」で動かす(`package.json` の `extensionKind: ["workspace"]`)。ローカルで開けば手元で、リモート接続中は接続先サーバーで動く。拡張は1つで済む。
- 対象 OS: Windows を主とし、macOS / Linux、リモート(SSH / WSL / Dev Container)でも動くこと。
- Windows では、VS Code 起動中は `Cache` などのフォルダがロックされていて消せない。
- VS Code には拡張ごとの「最終使用日」を取得する API がない(自動判定をしない理由の1つ)。

## 4. 検討した方式

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. サイドバーのツリー表示(採用)** | エクスプローラーと同じツリーで一覧を出す | 見た目が VS Code と一体。チェックボックス・行ボタン・右クリックメニューが標準部品で作れる。コードが少なく、リモートでもそのまま動く | 表の列揃えや棒グラフはできない |
| B. Webview パネル | HTML で専用画面を作る | 表・並べ替え・グラフなど自由 | コード量が A の2〜3倍。テーマ追従も自前 |
| C. コマンドパレットのみ | 一覧から複数選択して削除 | 最小の手間 | 全体を眺めて判断する用途に合わない |

ユーザーは A を選択。理由: 「容量順に並べて目につかせる、選んで消す、フォルダを開く」に必要な操作が標準部品だけで揃い、作りも保守も軽い。

## 5. 決まっていること

### 5.1 フォルダの場所の求め方

OS ごとのパスを決め打ちせず、拡張自身の保存場所から逆算する(Insiders 版・ポータブル版・リモートにも自動で対応するため)。

- `context.globalStorageUri` から親をたどり、名前が `User` のフォルダを見つける。その親がデータフォルダ(ローカル: `%APPDATA%\Code` など。リモート: `~/.vscode-server/data`)。
  - 「2つ上」と決め打ちしないのは、プロファイル機能を使うと `User/profiles/<id>/globalStorage/<拡張ID>` になるため(作り手の判断として記載)。
- 拡張機能フォルダ: インストール済みの拡張(`vscode.extensions.all` のうち組み込みでないもの)の `extensionPath` の親フォルダ。
  ローカル: `~/.vscode/extensions`、リモート: `~/.vscode-server/extensions`。
- リモートのサーバー本体: `vscode.env.appRoot` から、今使っているサーバーのフォルダを特定する。その親にある他のバージョンが「古いサーバー本体」。
  サーバーの置き場所は VS Code のバージョンで2通りある(`~/.vscode-server/bin/<コミット>` と `~/.vscode-server/cli/servers/Stable-<コミット>`)。両方を見る。CLI の古い実行ファイル `~/.vscode-server/code-<コミット>` も同じ扱い。

### 5.2 一覧に出すもの

ツリーの最上位は次のグループ。各グループは容量の大きい順に並べ、グループ自体も合計容量の大きい順に並べる。最上部に総合計を出す。

| グループ | 中身 | 削除 | 備考 |
|---|---|---|---|
| キャッシュ | `Cache`, `CachedData`, `Code Cache`, `GPUCache`, `CachedExtensionVSIXs`(データフォルダ直下) | 可 | 参考ページで「消してよい」とされる5つ。リモートにはないものもある(存在するものだけ表示)。削除の扱いは 5.5 参照 |
| その他のキャッシュ | `Crashpad`(クラッシュ時のダンプ), `Service Worker/CacheStorage`(Webview のキャッシュ), `CachedProfilesData` | 可 | 作り手の判断で追加。どれも VS Code が必要に応じて作り直す |
| ワークスペースの状態 ⚠ | `User/workspaceStorage/<ハッシュ>` を1件ずつ | 可(警告つき) | 各フォルダ内の `workspace.json` から、どのフォルダ/ワークスペースのものかを表示名にする。元のフォルダが存在しなければ「(元フォルダなし)」と印をつける。**今開いているワークスペースの分(`context.storageUri` の親)は削除不可** |
| ログ | `logs/<日時>` を1件ずつ | 可 | 今のセッションのログは削除不可 |
| ローカル履歴 | `User/History` | 可(警告つき) | ファイルの編集履歴(タイムライン)が消える |
| 古いサーバー本体 | リモートのみ。今使っているもの以外のサーバーフォルダと `code-<コミット>` | 可 | 今使っているものは一覧に出さない。そのフォルダから起動したプロセスが動いていれば(`/proc/*/exe` と `/proc/*/cmdline` で確認。リモートは Linux なので可能)「(使用中)」として削除不可にする。別の PC から接続中のサーバーを壊さないため(作り手の判断) |
| 拡張機能 | 拡張ごとのフォルダ | **不可**(アンインストールで対応) | 無効化済みには「(このウィンドウでは無効)」の印(5.3)。古いバージョンの残骸(`.obsolete` に記載のもの)は「(旧バージョン・次回起動時に VS Code が自動で掃除)」として容量だけ出す |
| 拡張のデータ | `User/globalStorage/<拡張ID>`(プロファイル利用時は `User/profiles/<id>/globalStorage/<拡張ID>` も)を1件ずつ | 持ち主の拡張が入っていないものだけ可 | 拡張によっては巨大になる。持ち主の拡張がどのプロファイルにも入っていないもの(`extensions.json` 群にも `vscode.extensions.all` にもない ID)には「(アンインストール済み)」の印をつけ、削除できる。持ち主がいるものは消すと拡張の状態が壊れるため表示のみ(ユーザー決定)。`ms-vscode.*` などの組み込み拡張、および `state.vscdb` などのファイルはこの判定の対象外(フォルダのみ対象) |

表示しないもの(誤って消せないようにする): `User/settings.json`, `keybindings.json`, `snippets`, `User/profiles`, `Backups`(未保存ファイルの控え。消すと未保存の編集が失われる), `User` フォルダそのもの、データフォルダそのもの、`~/.vscode-server` そのもの。

別のウィンドウで開いているワークスペースの `workspaceStorage` は判別しない。削除の確認ダイアログに「他のウィンドウで開いているフォルダの状態も消えます」と一文添えるだけにする(作り手の判断。Windows ではロックで失敗し、5.5 の「閉じてから削除」に回る)。

各行の表示: `名前   容量   (印)`。ホバーでフルパスを出す。

### 5.3 無効化済みの拡張の見分け方

`vscode.extensions.all` には有効な拡張しか入らない。拡張機能フォルダ内の `extensions.json`(インストール済み一覧)と突き合わせ、「インストール済みだが `vscode.extensions.all` にないもの」に印をつける。

この方法では「全体で無効」と「このワークスペースだけ無効」「読み込みに失敗」を区別できない。区別には VS Code 内部の SQLite を読む必要があり、依存が増えるのでやらない。代わりに印の文言を「(このウィンドウでは無効)」とし、事実だけを示す(作り手の判断)。

プロファイル機能を使っている場合:
- 拡張機能フォルダは全プロファイルで共有。インストール一覧は `User/profiles/<id>/extensions.json` にプロファイルごとにある。
- 他のプロファイルの一覧にだけ載っている拡張には「(他のプロファイルで使用)」の印をつける。アンインストールしても容量は空かない旨をホバーに出す。
- 一覧に出すのは今の環境の全体(プロファイルで絞らない)。

### 5.4 操作

| 操作 | 場所 | 動き |
|---|---|---|
| 更新 | ツリーのタイトルバー | 容量を再計算する |
| 選んだものを削除 | タイトルバー | チェックした行(削除可のものだけ)をまとめて削除。確認ダイアログに件数と合計容量を出す |
| この行を削除 | 行のボタン / 右クリック | 1件だけ削除。確認ダイアログあり |
| アンインストール | 拡張の行のボタン / 右クリック | VS Code 標準のアンインストール(`workbench.extensions.uninstallExtension`)を呼ぶ。チェックした複数の拡張にもまとめて実行できる。終わったら「リロードしますか?」と聞き、はいなら `workbench.action.reloadWindow` |
| フォルダを開く | 行のボタン / 右クリック | ローカル: `revealFileInOS` で OS のエクスプローラーで開く。リモート: OS のエクスプローラーでは開けないので、そのフォルダの親でターミナルを開き、削除コマンドを入力済み・未実行の状態にする |
| パスをコピー | 右クリック | フルパスをクリップボードへ |

### 5.5 削除の流れ

1. 確認ダイアログ(件数・合計容量・ワークスペースの状態やローカル履歴を含む場合はその影響)。
2. 1件ずつ、ゴミ箱に入れず完全に削除する(目的がディスク容量のため。ゴミ箱だと空くまで容量が減らない)。
   - ただし `Cache`, `CachedData`, `Code Cache`, `GPUCache` は VS Code 本体が使用中のため、**OS を問わず**その場では消さない(macOS / Linux では起動中でも消せてしまい、動作が不安定になるおそれがある)。これらは最初から 3. の「閉じてから削除」に回す(作り手の判断)。
3. 使用中で消せなかったもの(Windows のロックなど)と上記4つは、まとめて「VS Code を閉じてから削除が必要」と通知する。通知には「フォルダを開く」ボタンと「削除コマンドをコピー」ボタン(OS に合わせた PowerShell / シェルのコマンド)をつける。中途半端に一部だけ消えたフォルダも同じ扱い。
4. 終わったら容量を再計算して、空いた容量を通知する。

### 5.6 容量の計算

- 拡張内で非同期にフォルダを再帰的にたどって合計する(シンボリックリンクはたどらない)。外部コマンドに頼らないので OS を問わない。
- 拡張機能フォルダはファイル数が多く時間がかかるため、計算中は行に「計算中…」と出し、終わった順に表示を更新する。キャンセル可能。
- ビューを最初に開いたときと「更新」を押したときだけ計算する(常時監視はしない)。

### 5.7 表示言語

画面の文言は日本語。

### 5.8 配布

自分用に `.vsix` を作り、手元に入れる(ユーザー決定)。Marketplace には公開しない。
リモートで使うときは、拡張機能画面の「SSH: <ホスト> にインストール」などで接続先にも入れる。README にこの手順を書く。

## 6. 作り手に任せること

- プロジェクト構成、ビルドツール、テストの書き方(容量計算・グループ分け・並べ替え・パスの導出は純粋な関数にしてテストできるようにすること)。
- アイコン、ビューの置き場所(専用のアクティビティバーアイコンを想定)。
- 容量計算の並列度、キャンセルの実装方法。
- `workspace.json` の表示名の作り方(フォルダ名 + パスなど)。
- 容量の単位表記(KB/MB/GB の切り替え)。
